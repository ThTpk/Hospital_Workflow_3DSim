# จำลองการทำงานภายในโรงพยาบาล 3 มิติ

แบบจำลอง 3 มิติแบบโต้ตอบของการไหลของผู้ป่วยในโรงพยาบาล — อาคาร 2 ชั้นที่ตัดผ่าดูได้
มีผู้ป่วยเดินผ่านแผนกต่าง ๆ ตามเส้นทางจริง และ panel ตัวเลขที่อ่านจากโมเดลคิวตัวเดียวกับที่สั่งให้คนไข้เดิน

**เปิดใช้งาน:** https://thtpk.github.io/Hospital_Workflow_3DSim/

---

## สิ่งที่กดเล่นได้

| กลุ่ม | ทำอะไร |
|---|---|
| **เลือกแผนก** | กดชื่อแผนกในรายการ กล้องบินไปหา แยกชั้นให้อัตโนมัติ และกราฟเปลี่ยนไปอ่านคิวของแผนกนั้น |
| **ตัดผ่าอาคาร** | `เปิดหลังคา` · `ทึบ` · `ตัดขวาง` · `X-ray` (ผนังโปร่งเห็นคนเดินทะลุ) |
| **ชั้น** | `ทั้งอาคาร` ยกชั้น 2 ลอยขึ้นให้เห็นพร้อมกัน · `ชั้น 1` · `ชั้น 2` |
| **มุมกล้อง** | `ภาพรวม` · `ผังจากบน` · `ระดับสายตา` — ลากเมาส์หมุน/ซูมเองได้ตลอดเวลา |
| **เวลา** | เล่น/หยุด · ความเร็ว 1×–60× · ลากแถบเวลาย้อนกลับไปดูช่วงที่คิวแตกได้ |
| **ปรับสถานการณ์** | เลื่อนจำนวนเจ้าหน้าที่แต่ละจุด จำนวนผู้ป่วยเข้า และสัดส่วนที่ส่งตรวจแล็บ — เห็นผลทันทีโดยไม่ต้องเริ่มใหม่ |
| **สถานการณ์สำเร็จรูป** | `วันปกติ` · `เช้าวันจันทร์` · `อุบัติเหตุหมู่` · `แพทย์ลา 2 คน` |
| **คลิกที่ตัวคนไข้** | กล้องล็อกตาม และขึ้นประวัติว่าเขารอที่ไหนไปกี่นาที |
| **ปล่อยไว้ 25 วินาที** | พาชมเองอัตโนมัติ แตะอะไรก็คืนการควบคุมทันที |

แป้นลัด: `เว้นวรรค` เล่น/หยุด · `1`–`4` โหมดตัดผ่า · `Esc` ยกเลิกการเลือก

## ของที่อยู่ในห้อง

แต่ละแผนกมีเฟอร์นิเจอร์และเครื่องมือตามหน้าที่จริงของมัน

| แผนก | มีอะไรอยู่ |
|---|---|
| เวชระเบียน / การเงิน | โต๊ะพร้อมคอมพิวเตอร์ เก้าอี้ ชั้นเก็บแฟ้ม เครื่องรูดบัตร |
| คัดกรอง | โต๊ะคอม เครื่องวัดความดัน เครื่องชั่งน้ำหนักพร้อมที่วัดส่วนสูง |
| OPD ตรวจโรค | 8 คูหา แต่ละคูหามีโต๊ะคอม เก้าอี้แพทย์ เก้าอี้ผู้ป่วย เตียงตรวจ ม่านกั้น |
| ห้องปฏิบัติการ | จุดรับสิ่งส่งตรวจ เครื่องวิเคราะห์อัตโนมัติ เครื่องปั่นเหวี่ยง กล้องจุลทรรศน์ |
| X-ray | เตียงเอกซเรย์ เสาและแขนหลอดเอกซเรย์ ห้องควบคุมพร้อมกระจกตะกั่ว |
| ห้องยา | ชั้นยาหลายแถว จุดจ่ายยาพร้อมคอม โต๊ะจัดยา |
| ER | เตียงพร้อมราวกั้น จอสัญญาณชีพ เสาน้ำเกลือ ม่านกั้นเตียง เคาน์เตอร์พยาบาล รถฉุกเฉิน |
| IPD | 120 เตียง ตู้ข้างเตียง เสาน้ำเกลือ เคาน์เตอร์พยาบาล |
| ห้องผ่าตัด | เตียงผ่าตัด โคมไฟผ่าตัด เครื่องดมยาสลบ จอสัญญาณชีพ โต๊ะเครื่องมือ |

**จำนวนเจ้าหน้าที่ในห้องอ่านจากโมเดล ไม่ใช่ตัวเลขตายตัว** — เลื่อนสไลเดอร์เพิ่มแพทย์ OPD
จาก 8 เป็น 14 คน แล้วจะเห็นคนในคูหาเพิ่มขึ้นจริง 6 คน สีชุดแยกตามวิชาชีพ
(ขาว = แพทย์, เขียวอมฟ้า = พยาบาล, ฟ้า = เจ้าหน้าที่เวชระเบียน/การเงิน, เทา = นักเทคนิค)

ส่วนเฟอร์นิเจอร์ยึดตาม**ขนาดห้องตามแบบ** ไม่ใช่จำนวนคนเข้าเวร — หมอลา 2 คน
ห้องตรวจก็ยังมี 8 ห้องเท่าเดิม แค่มีคนนั่งไม่ครบ

## รันบนเครื่องตัวเอง

ไม่มี build step ไม่ต้อง `npm install` — แต่ต้องเสิร์ฟผ่าน http เพราะ ES modules โหลดจาก `file://` ไม่ได้

```bash
python serve.py
```

แล้วเปิด http://localhost:8766

`serve.py` คือ `http.server` ที่ปิด cache ไว้ ใช้ตอนพัฒนาเพื่อไม่ให้เบราว์เซอร์
เก็บไฟล์ `.js` ตัวเก่าไว้จนแก้โค้ดแล้วไม่เห็นผล (เจอปัญหานี้จริงตอนสร้าง)
ถ้าแค่อยากเปิดดูเฉย ๆ `python -m http.server 8765` ก็ใช้ได้

## สมมติฐานของแบบจำลอง

ตัวเลขตั้งต้นอิงโรงพยาบาลทั่วไปขนาดกลางของไทย **ไม่ได้วัดจากโรงพยาบาลจริงแห่งใด**
ถ้าจะใช้งานจริงต้องเปลี่ยนเป็นข้อมูลของโรงพยาบาลนั้น (แก้ที่ `STATION_DEFS` และ `OPD_ARRIVALS` ใน `src/sim.js`)

| จุดบริการ | จำนวน | เวลาบริการเฉลี่ย |
|---|---|---|
| เวชระเบียน | 4 | 2.5 นาที |
| คัดกรอง | 5 | 3 นาที |
| OPD ตรวจโรค | 8 | 6 นาที |
| ห้องปฏิบัติการ | 4 | 6 นาที + รอผล 22 นาที |
| X-ray | 3 | 7 นาที + รอผล 12 นาที |
| ห้องยา | 6 | 4 นาที |
| การเงิน | 4 | 2 นาที |
| ER | 6 เตียง | 38 นาที (ถ่วงตามระดับความรุนแรง) |
| IPD | 120 เตียง | 3 วัน |
| ห้องผ่าตัด | 3 | 95 นาที |

- ผู้ป่วยนอก ~480 คน/วัน พีค 86 คน/ชม. ช่วง 08:00 (รูปแบบไทย: มารอตั้งแต่ก่อนเปิด ลดลงชัดเจนหลังเที่ยง)
- ผู้ป่วย 1 คนพบแพทย์เฉลี่ย ~1.45 ครั้ง เพราะ 45% ถูกส่งตรวจแล้วกลับมาฟังผล
- เวลาบริการแจกแจงแบบ lognormal (เบ้ขวา — คนส่วนใหญ่เร็ว บางคนนานมาก)
- ผู้ป่วยมาแบบ non-homogeneous Poisson
- ER จัดคิวตามความรุนแรงก่อนเวลามาถึง (อิงแนวคิด ESI ระดับ 1–5)
- เวลาเดินคิดจากระยะทางจริงบนผัง ที่ความเร็ว ~72 ม./นาที บวกความต่างระหว่างบุคคล
- ตัวสุ่มมี seed คงที่ — ลากเวลากลับไปจุดเดิมจะได้ "วันเดิม" เป๊ะ ๆ

### ทำไมตั้งแพทย์ OPD ไว้ 8 คน

```
480 คน/วัน × 1.45 ครั้ง × 6 นาที = 4,176 นาที/วัน
÷ 540 นาทีทำการ (07:00–16:00)      = ต้องมี 7.7 คน
```

ตั้ง 8 คน ได้ utilization ~67% รอเฉลี่ย ~20 นาที ซึ่งตรงกับ OPD โรงพยาบาลรัฐของไทย
และอยู่ใต้ "หน้าผาความอิ่มตัว" พอดี — ลดเหลือ 6 คน เวลารอพุ่งเป็น ~70 นาทีทันที
ลองเลื่อนสไลเดอร์ดูได้

## ข้อจำกัดที่ควรรู้

- เป็น **discrete-event simulation ของคิว** ไม่ใช่การจำลองการรักษา ไม่มีเรื่องโรค ยา หรือผลการรักษา
- ไม่มีเวรเปลี่ยนกะ พักเที่ยง หรือเจ้าหน้าที่ทำงานหลายหน้าที่พร้อมกัน
- ห้องผ่าตัดรับเฉพาะเคสจาก ER ไม่มีผ่าตัดนัดล่วงหน้า (elective)
- คนไข้ไม่เดินหลบกัน — เดินตามเส้นทางสั้นสุดบนกราฟทางเดิน ไม่มี collision avoidance
- เจ้าหน้าที่ยืนอยู่กับที่ ไม่ได้เดินไปมาหรือหยิบจับอุปกรณ์
- เมื่อคิวยาวเกินความจุของโถงรอ คนจะยืนซ้อนแน่นขึ้นแทนที่จะล้นออกนอกห้อง
  (คิว OPD เช้าวันจันทร์พีคถึง ~200 คน ซึ่งไม่มีโถงไหนใส่เป็นแถวเรียงได้)
- ไม่มีใครเลิกรอกลางคัน (balking/reneging) ซึ่งของจริงเกิดขึ้นเมื่อคิวยาวมาก

## เทคนิค

- three.js r186 vendor ไว้ใน repo ไม่พึ่ง CDN — เปิดจากไฟล์ในเครื่องก็ทำงาน
- ไม่ใช้ postprocessing และไม่ใช้ addon ใด ๆ เพื่อให้ลื่นบนกราฟิกออนบอร์ด
- เลือกชั้นคุณภาพจาก **GPU จริง** (ถาม `WEBGL_debug_renderer_info`) ไม่ใช่เดาจากจำนวนคอร์ CPU
  เพราะโน้ตบุ๊ก 16 คอร์ที่ใช้กราฟิก Intel ออนบอร์ดจะถูกจัดเป็นเครื่องแรงทั้งที่ไม่ใช่
- ผู้ป่วยและเตียงเป็น `InstancedMesh` — 120 เตียงและผู้ป่วยหลายร้อยคนใช้ draw call เดียวต่อชุด
- เฟอร์นิเจอร์และเครื่องมือทั้งโรงพยาบาล (~1,070 ชิ้น) ประกอบจาก primitive เพียง 3 แบบ
  (กล่อง / ทรงกระบอก / ทรงกลม) รวมเป็น InstancedMesh อย่างละตัวต่อชั้น
  ถ้าสร้างแยกเป็น Mesh ละชิ้นจะได้หลายร้อย draw call ซึ่งเป็นตัวฆ่าเฟรมตัวจริง
- ป้ายชื่อแผนกตั้ง `sizeAttenuation: false` ให้มีขนาดคงที่บนจอ
  ถ้าปล่อยให้โตตามระยะ พอกล้องบินเข้าห้องป้ายจะบังทั้งห้อง
- ผนังทึบโดยปกติ โปร่งเฉพาะโหมด X-ray เพราะวัสดุโปร่งซ้อนกันกินแบนด์วิดท์การวาดอย่างหนัก
- เปิด `window.hospital` ไว้ให้ตรวจสอบจาก console เช่น `hospital.debug()`
